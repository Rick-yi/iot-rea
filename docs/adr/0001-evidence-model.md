# ADR 0001：证据优先，结论四分

## 状态

已采纳，2026-11-18。

## 背景

物联网协议逆向最容易犯的错误是把"没抓到"说成"不存在"，把"这段字节看起来像温度"写成事实。一次抓包、一个过滤器、一段窗口都会让结论失真，而下游（写解析器、做重放、做固件比对）无法分辨哪些是观察、哪些是猜测。

## 决策

所有对外结果只通过 `Evidence` 携带，并把结论分成四类：

1. **观察（observation）**：生产者输出或文件内容本身。保留原始行、stderr、帧号。
2. **推导（derivation）**：对观察的确定性计算，如 SHA-256、偏移、区域合并。
3. **推断（inference）**：带分数的假设，必须给出匹配数、总数和反例。
4. **未知（unknown）**：未能建立的部分，显式列出。

配套的硬规则：

- 源文件路径 + SHA-256 + 大小随证据返回；工具记录配置路径、解析路径、版本 banner、可执行文件 digest。
- 空结果只描述所选窗口、过滤器与读入范围，不允许表述为"不存在"。
- 输出超限、超时、摘要不一致都直接失败，不返回截断的成功。
- 每页携带 `output_window {offset, requestedLimit, total, returned, hasMore}`；混用不同 digest 的分页视为错误。

## 后果

- 结论可以复核：任何字段都能回到具体帧、具体参数和具体工具版本。
- 结果结构更长，但下游不需要猜语义来源。
- 推断必须给出反例；没有反例的"满分"也要注明样本量。
- `docs/specs/<device>/spec.md` 成为唯一事实来源，未知项不会被悄悄补全。
